# 本机（zzy-X830）约定

## 工作日志：去哪

- **本机所有 Codex 笔记（工作日志、整理出来的文档、说明、答复整理，一律）固定写到这里：**
  `~/Desktop/codex_create_note/<日期>/上装/N.md`
  日期文件夹形如 `2026-10-08`，`上装/` 是日期目录下的子文件夹；两者都由 SessionStart 钩子
  （`~/.codex/work-log.sh`）在每次开新会话时自动建好并给出文件路径。
  **这是默认行为，不需要用户每次交代，也绝不允许写到别的位置。**
- `~/Desktop/cyf_note/<日期>/N.md` 只是钩子的**兜底**：只有 `codex_create_note` 目录不存在
  （比如刚装好的新电脑、还没 clone 仓库）时才会用到。本机仓库在，就不会再往 cyf_note 写。
- `~/Desktop/codex_create_note/` 这个仓库两台电脑共用：日期目录根下的 `N.md` 是**另一台电脑**写的，
  不要覆盖、不要续号、不要合并；本机只往 `<日期>/上装/` 里写。

### 序号怎么定（用户会自己给文件加标题）

- 用户可能把 `2.md` 改名成 `2  标题.md`（序号后面加标题；仓库里也有 `0  合并.md`、
  `1  ROS 工作区代码阅读法 skill.md` 这种）。
- 判断"下一篇用几号"时，**只看文件名开头的 1~3 位数字**：
  `2.md` / `2 标题.md` / `2_标题.md` / `2-标题.md` 都算**第 2 篇**。
  4 位及以上**不算编号**：`上装/` 里有 `2026-10-08_启动命令_建图_导航_加载地图.md` 这类
  日期前缀的文件，按老的 `^[0-9]+` 规则会被误算成 2026，所以把编号限定在 1~3 位。
- **下一篇 = `上装/` 里已有序号的最大值 + 1**（例：已有 1~13 → 下一篇是 `14.md`）。
- **绝不因为 `N.md` 不见了就重建同号文件**（用户改名成 `N 标题.md` 后，不要补写 `2.md`/`N.md`）；
  也不要覆盖、改名、合并用户的文件。

## 工作日志：怎么写（2026-10-08 用户明确要求，必须遵守）

- **一律新建一个 md 文件写入，绝不追加/合并到已有的 md 文件里。**
  只有用户明确说"和之前的写在一起 / 追加到某个文件"时，才写进已有文件。
  这条对**所有 md 笔记**都适用：工作日志、整理出来的文档、说明、答复整理，统统新建文件。
- 内容只写**最终有效**的东西，中文，固定三部分：
  1. **执行的操作**：按顺序列出实际运行的关键命令或改动，以及各自的目的和结果。
  2. **遇到的问题**：说清现象、报错原文、触发条件。
  3. **解决方法**：写详细的最终解决步骤，别人照着能复现。
- 不要写试错的弯路和无效思路，只保留最后真正解决问题的方案。

## 整理完要推送到仓库

- 整理完记得 `git pull --rebase` 再 `git push`（另一台电脑可能刚推过）。
- 推送网络：**优先用代理**
  `export https_proxy=http://127.0.0.1:7897 http_proxy=http://127.0.0.1:7897 all_proxy=socks5://127.0.0.1:7897`
  ；代理不通（Clash 没起）时清掉代理直连：
  `env -u http_proxy -u https_proxy -u all_proxy -u HTTP_PROXY -u HTTPS_PROXY -u ALL_PROXY git push origin main`。
- 推完确认远端 = 本地：`git log --oneline -1 && git rev-parse origin/main`。
